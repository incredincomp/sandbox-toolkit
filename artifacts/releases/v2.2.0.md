# sandbox-toolkit v2.2.0

Release date: 2026-05-28

## Highlights

- Added three Windows 11-focused operational profiles:
  - `analysis` (internet-enabled modern analyst baseline)
  - `detonation` (restricted, no-network detonation posture)
  - `forensics` (strict offline static/forensic triage posture)
- Refactored profile defaults to include explicit profile-driven `Networking` and `VGpu` policy.
- Added reference profile templates:
  - `sandbox-profiles/analysis.wsb`
  - `sandbox-profiles/detonation.wsb`
  - `sandbox-profiles/forensics.wsb`
- Added analyst workflow scripts:
  - `scripts/Invoke-SampleTriage.ps1`
  - `scripts/Export-AnalysisArtifacts.ps1`
  - `scripts/Reset-SandboxWorkspace.ps1`

## Security hardening included in this tag

- Shared-folder validation now rejects selected host folders that contain descendant reparse points/junctions.
- Template invocation no longer implicitly carries writable shared-folder mappings across explicit `-SharedFolder` overrides unless `-SharedFolderWritable` is explicitly provided.
- Audit mode now fails if generated `.wsb` artifacts contain unexpected extra host-folder mappings.
- `Invoke-SampleTriage.ps1` now uses bounded streaming reads with a configurable byte cap (`MaxBytes`) to avoid out-of-memory behavior on oversized samples.
- `Export-AnalysisArtifacts.ps1` now validates mapped shared-root destinations before write/export operations and handles empty artifact directories gracefully.

## Operational notes

- Keep `-Validate`, `-DryRun`, and `-Audit` in pre-launch workflows for deterministic readiness and artifact checks.
- For sensitive workflows, keep networking disabled profiles (`detonation`, `forensics`) and prefer read-only shared-folder mappings.
